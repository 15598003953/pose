# 测试结果记录

适用日期：2026-11-12。

测试结果记录用于真实摄像头、实际 RFID 和生产消息服务器验证。
它保存识别数据和对应图像，不能代替人工确认身份是否正确。

## 使用方式

1. 在“测试记录”页启用“测试结果记录”。
2. 按需填写测试编号，也可以留空。
3. 启动联调，按场景执行测试。
4. 运行期间自动保存识别数据、标注画面、目标裁剪图和人物库参考图。
5. 停止联调后，保存本次会话目录。

## 自动记录

`field_test.json` 保存测试元数据和会话结果，主要字段包括：

- `test`：测试编号、人员、地点、场景和说明。
- `started_at`、`ended_at`、`duration_ms`：会话时间。
- `runtime`：是否为发布包、Python 版本和 Windows 环境。
- `configuration`：消息方式、视频地址摘要、启用区域、识别阈值、识别间隔和画面尺寸。
- `counts`：消息、旅客、绑定、未绑定、错误和未发送数量。
- `event_counts`：识别、绑定、人工核对、MQTT 状态和后台错误数量。

`test_results.jsonl` 每行是一条识别结果，主要字段包括：

- `captured_at_ms`、`completed_at_ms`：图像采集和识别完成时间。
- `regions`：区域、候选身份、轨迹编号、人体检测分数、重识别分数、
  第二名分数、分差、状态和人体框。
- `metrics`：设备、处理耗时、特征提取耗时、跳帧和消息等待数量。
- `images`：原始整帧、标注整帧和目标裁剪图的相对路径。
- 候选中的 `image_path`、`reference_images`：当前目标图及收到的候选身份参考图路径。
- `ranked_candidates`：最多三名候选的排名、完整身份、分数和参考图路径。
  图库不足三人时，记录全部候选。
- `accepted_label`：程序已确认的身份，未确认时为空。`label` 仍表示第一候选。
- `score_source`：`track_history` 表示轨迹历史得分，
  `current_feature` 表示当前无轨迹目标的得分，
  `locked_confirmation` 表示首次锁定时保存的得分。
- `frame_index`、`feature_frame_index`：当前处理帧和最近提取特征的处理帧编号。
  编号从零开始，仅在同一区域、同一匹配器内比较。

`test_images/` 保存与识别结果对应的图片：

- `reid_frames/`：未绘制标注的整帧和带框、状态、分数的整帧，使用 JPEG。
- `reid_crops/`：候选目标的原始裁剪图，使用 PNG，避免再次有损压缩。
- `gallery/`：收到的上半身图和人脸图，解码后使用 PNG 保存。

`field_test_events.jsonl` 每行是一条辅助事件，事件类型包括：

- `session_started`、`session_stopped`
- `person_collected`
- `recognition`
- `binding_decision`
- `mqtt_state`
- `worker_error`
- `manual_observation`

识别事件与 `test_results.jsonl` 使用同一份识别数据，并包含图片相对路径。
日志不保存视频帧和图片的 Base64 正文。

程序记录每个实际处理的识别帧，包括低分、未匹配、无人和人物库为空的情况。
跳过的摄像头帧不属于识别帧，不保存图片。界面只刷新最新结果，文件记录独立执行。
整帧标注包含当前候选目标，队首筛选未采用的其他目标不属于候选记录。
当前目标裁剪图对应本帧的位置；分数可能来自特征缓存、轨迹历史或锁定时的结果。
`score` 是重识别相似度，不是识别正确率。`detector_score` 是人体检测分数。
第一候选有具体身份，不表示程序已经确认。界面将未采用结果标为“未确认”；
旅客证据仅接收已匹配结果，避免错误候选替换已确认的截图。
身份锁定后的排名、分差和特征帧编号保留确认时的值，不能当成当前重新比对的结果。
关闭记录后不生成测试结果和图片。性能日志由“性能调试”页的独立开关控制。
持续记录会增加磁盘用量和处理耗时；保存失败会显示具体错误，并写入汇总统计。
人物实际身份及图片是否对应同一人，仍需人工标注。

## 现场测试项目

| 项目 | 建议记录内容 |
| --- | --- |
| 闸机抓拍 | 应抓到人数、实际人数、漏抓、重复抓拍、图片清晰度、旅客编号 |
| 旅客入库 | 入库时间、图片来源、完整旅客编号、图片与现场人员是否对应 |
| 重识别 | 前三名候选、实际身份、相似度、分数差、确认身份、锁定状态 |
| 目标跟踪 | 遮挡返回、离开清除、队首切换、轨迹编号连续性 |
| 行李框绑定 | RFID、预期旅客、实际旅客、状态、依据、位置时差、停留时长 |
| 消息链路 | 主题、消息数、接收时间、重复事件、无效消息、重连、未发送 |
| 性能 | CPU/GPU、采集帧率、识别帧率、处理耗时、位置延迟、跳帧数 |
| 环境条件 | 摄像头位置、分辨率、光照、遮挡、人数、网络、截图和视频时间点 |

后续测试报告可以按“测试场景、输入条件、识别数据、检测图像、
结论和问题”整理。`test_results.jsonl` 用于识别结果，
`test_images/` 用于图像证据，`messages.jsonl` 用于消息时序，
`field_test_events.jsonl` 用于辅助事件，`decisions.jsonl` 用于绑定依据，
`performance.jsonl` 用于性能统计，`runtime.log` 用于错误和连接过程。
