# 人包绑定 Qt 工作台

桌面入口是 `src/pose_project/apps/binding_app.py`，使用现有 Conda 环境 `mmpose`。
程序复用 `passenger_tray_binding.py` 中的判定规则。
无需安装新依赖，现有 `requirements.txt` 已包含 PyQt5 和 paho-mqtt。

## 启动

首次运行先按项目根目录的 `README.md` 安装本地源码。

在 `D:\code\mediapipe-master` 下执行：

```powershell
conda run --no-capture-output -n mmpose python -m pose_project binding
```

也可以指定其他算法配置：

```powershell
conda run --no-capture-output -n mmpose python -m pose_project binding --config .\pose\configs\binding_config.json
```

程序默认选择现有模拟日志，默认关闭 MQTT 输出。
点击“开始”即可回放，支持调整速度、暂停和继续。
运行期间锁定接口和参数，停止后可以重新设置。
每次开始都会建立新会话，上一会话需要的结果应先导出。

## 界面

- 数据接口：文件、MQTT、HTTP 三种输入；支持选择文件和自定义消息字段。
- 模拟数据：选择场景模板和保存目录，设置随机种子、采集间隔及传输延迟。
- 绑定参数：调整停留时间、等待时间、坐标有效期和延迟补偿。
- 区域配置：增加或移除供框台，修改供框台及操作区的像素坐标。
- MQTT 输出：单独设置结果服务器、端口、认证、TLS、主题和 QoS。
- 区域视图：显示最新检测框、操作区和选中旅客。悬停检测框可查看原始 ID。
- 绑定结果：按状态筛选，选择一行后查看候选人停留时间和绑定返回值。
- 导出结果：生成新的结果目录，保存完整判定、成功绑定和本次算法配置。

区域视图按检测框坐标绘制位置示意。
P01、P02 等是当前会话的显示编号，结果消息仍采用完整旅客 ID。
区域视图展示最新位置，候选人依据对应选中的历史推框事件。
目前未接入视频播放。

“加载”和“另存”操作处理算法参数、区域和输入主题。
另存到已有文件时，程序先创建带时间的 `.bak` 备份。
MQTT 密码仅保存在运行内存中，不写入算法配置或导出结果。

## 文件输入

选择“本地文件回放”，再选择 `replay.jsonl`。
程序保留文件中的接收时间，按真实时间间隔和所选倍速回放。
文件结束时生成剩余判定，MQTT 发送队列继续等待连接或确认。
文件模式的消息字段沿用离线日志格式，字段映射仅用于实时输入。
日志必须按 `received_at_ms` 升序排列。

默认模拟数据含 3609 条消息和 9 次推框。
数据生成方式见 `BINDING_SIMULATION.md`。

## 生成模拟数据

在“数据接口”中选择“本地文件回放”，点击“生成模拟数据”。
默认加载项目自带的场景模板，并自动填写一个新的保存目录。

生成窗口支持修改：

- 场景模板 JSON 和保存目录。
- 随机种子；相同模板、参数和种子可以复现相同数据。
- 起始时间，格式例如 `2026-10-21T09:00:00+08:00`。
- 更新间隔，默认 200 毫秒。
- 检测框坐标扰动，单位为像素。
- 检测消息、光电信号的最小和最大传输延迟，单位为毫秒。

总时长、区域、旅客轨迹和推框事件由模板定义。
如需修改场景，复制并编辑 `configs/binding_simulation_config.json`，再选择复制后的文件。
更新间隔必须整除场景总时长；程序会检查时间、坐标和事件是否有效。
生成过程使用后台线程。写入完成后，生成窗口自动关闭。
生成期间暂时禁止关闭窗口，避免中断文件写入。

输出目录包含 `detections.jsonl`、`rfid.jsonl`、`replay.jsonl`、
`expected_bindings.jsonl` 和 `manifest.json`。
`manifest.json` 保存本次实际使用的模板参数和数据数量。
程序拒绝写入已有非空目录，也不会修改原始模板。
若写入失败，程序显示错误并保留已写入的文件；重试时选择新的空目录。

生成成功后，工作台自动选中 `replay.jsonl`，同步模板中的区域和输入主题。
当前算法参数、MQTT 服务器和输出开关保持原设置。
运行记录中显示保存目录和数据数量，点击“开始”即可回放。
生成操作只写入本地文件；回放时是否发送绑定结果由 MQTT 输出设置决定。

## MQTT 输入

检测端对接协议见 `MQTT_DETECTION_PROTOCOL.md`，包含必填字段、身份规则、发送频率和联调要求。

选择“MQTT 订阅”，填写已运行的 MQTT 服务器。
检测与 RFID 使用各自的主题，默认分别为：

```text
simulation/binding/detections
simulation/binding/rfid
```

主题可修改，当前使用具体主题名称，不支持 `+`、`#` 通配符。
输入订阅使用 QoS 1。
用户名和密码可留空，TLS 使用默认受信任证书校验。

检测消息示例：

```json
{
  "roi_id": "A",
  "captured_at_ms": 1792544400000,
  "detections": [
    {
      "passenger_id": "A-a6deca95bec249a4b5b0124ec6348ff6-2026-10-21",
      "bbox_xyxy": [320, 255, 480, 495]
    }
  ]
}
```

`captured_at_ms` 必须填写实际采集时刻，单位是 Unix 毫秒。
示例中的固定时间仅用于说明格式。
每条检测消息应包含当前区域的完整人员列表，无人时发送空数组。
检测端时间与工作台所在电脑的时间应保持同步。
程序保留原始旅客身份，不重新生成旅客 ID。

RFID 消息示例：

```json
{
  "roi_id": "A",
  "rfid": "RFID-A-0001",
  "event_id": "reader-A-push-0001"
}
```

RFID 不需要硬件时间戳。
程序使用收到消息时的本机时间，作为此次推框的参考时刻。
实时输入中的外部 `received_at_ms` 不会替代本机接收时间。

`event_id` 可选，同一次推框重发时应保留相同编号。
同一会话内，相同区域与事件编号只处理一次。
同一事件编号对应不同 RFID 时，程序记录输入错误。
MQTT 重传标记与报文编号也用于过滤当前连接中的重复报文。
程序忽略 MQTT 保留的 RFID 消息，避免把历史推框当作新事件。
输入端应为新推框使用新事件编号，避免将同一个物理框的再次使用误认为重发。
当前去重记录在会话内有效，尚未保存跨重启的事件状态。

## HTTP 输入

选择“HTTP 接收”，默认监听 `127.0.0.1:8765`。
在工作台开始接收后，其他程序可以发送：

```text
POST http://127.0.0.1:8765/detections
POST http://127.0.0.1:8765/rfid
Content-Type: application/json
```

请求正文与 MQTT 消息示例相同。
HTTP 202 表示消息已进入接收队列。
在界面的运行记录中查看字段错误，通过结果列表或 MQTT 查看绑定结果。
单条请求正文最大为 1 MiB。

RFID 请求示例：

```powershell
$body = @{
    roi_id = "A"
    rfid = "RFID-A-0001"
    event_id = "reader-A-push-0001"
} | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8765/rfid" -Method Post -ContentType "application/json" -Body $body
```

HTTP 接收端不提供登录和 HTTPS。
默认监听地址只供本机使用；跨设备接入应使用受控局域网和合适的网络访问限制。
若需互联网或不受控网络接入，应在前置服务中提供认证和 TLS。

## 自定义消息字段

实时输入支持在“消息字段”中填写点号分隔的路径。
例如，区域位于 `station.zone`，采集时间位于 `frame.time`，可分别填写对应路径。
人员列表也可以设置为 `frame.people`。

旅客 ID 和检测框的路径，相对于人员列表的每一项填写。
其余字段路径相对于整条消息正文填写。
如果输入采用 `{"payload": {...}}` 包装，路径相对于 `payload` 内容填写。
检测框仍须是 `[左, 上, 右, 下]` 数组；采集时间仍须是整数毫秒。

## MQTT 输出与导出

勾选“通过 MQTT 发送成功绑定”，填写输出服务器和结果主题。
输出服务器可以与输入服务器不同，结果主题默认是 `pose/bindings`。
输入主题与结果主题须不同。
默认 QoS 为 1，发送时关闭保留消息。

每次成功绑定仅发送这三个字段：

```json
{
  "roi_id": "A",
  "passenger_id": "a6deca95bec249a4b5b0124ec6348ff6-2026-10-21",
  "rfid": "RFID-A-0001"
}
```

旅客 ID 保留随机唯一字段和首次出现日期，去掉旧格式中的区域前缀。
同一旅客连续使用多个框时，旅客 ID 保持不变。
未绑定及多人封存的事件仍显示在界面中，不发送成功绑定消息。

输出服务器尚未连接时，成功绑定先进入待发送队列。
连接恢复后，程序继续发送当前会话中的待发送结果。
QoS 0 显示“已发送”，QoS 1、2 收到服务器确认后显示“已确认”。
服务器确认表示 MQTT 传输确认，上位系统的业务入库状态由上位系统反馈。
停止会话时，尚未发送或尚未确认的结果会标记对应状态。
发送队列目前保存在内存中，停止或退出前可导出结果。

“导出结果”保存：

- `bindings.jsonl`：供上位系统读取的三个绑定字段。
- `decisions.jsonl`：包含候选人依据的完整判定。
- `run.json`：本次算法参数、来源类型和消息数量。
