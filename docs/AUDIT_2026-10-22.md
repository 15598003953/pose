## 已修复的问题

| 优先级 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 人体检测将右下角坐标传给需要宽高的去重接口，可能误删相互分离的人体框 | 去重前转换为左、上、宽、高；检测输出仍保留原坐标格式 |
| P1 | 模型采样按帧号取余，推理跳帧与采样间隔组合后，四秒片段可能延长到十余秒 | 按视频时间判断采样间隔；时间倒退或长时间中断时清除旧片段 |
| P1 | 切换视频未先停止旧线程，界面可能显示旧视频，多个线程也可能共用模型 | 打开新视频或更换模型前停止旧线程 |
| P1 | 视频线程停止超时后仍丢失引用，旧推理可能与新会话同时运行 | 保留未退出线程，等待后台推理结束后再释放日志和通信对象 |
| P1 | 修改区域后，旧推理仍可能更新识别缓存或写出动作事件 | 识别缓存按版本隔离；缓存和事件写入前检查版本 |
| P1 | 取流线程仍在原生读取时，停止操作提前释放视频对象 | 由读取线程负责释放；等待超时保留对象和线程引用 |
| P1 | 动作 MQTT 发布没有检查返回码，发送失败仍显示成功 | 检查发布返回码并保存失败信息 |
| P2 | 姿态预处理直接修改检测数组中的关键点，影响调用方复用原始结果 | 预处理复制检测数据 |
| P2 | 规则识别以调用次数计算停留，跳帧后动作持续时间发生变化 | 使用原视频帧跨度计算持续时间 |
| P2 | 拖动播放进度继续使用之前的动作历史 | 跳转后清除识别缓存及旧叠加信息 |
| P2 | 后台推理异常只终止线程，界面无法获知错误 | 通过界面错误信号报告异常，并清除忙碌状态 |
| P2 | 配置文件为合法 JSON 数组或 null 时，应用启动会出错 | 视频来源与动作 MQTT 配置要求顶层对象，否则使用默认配置 |
| P2 | ONNX Runtime 执行异常时提前返回，显式启用的备用实现无法执行 | 异常后继续检查并调用 OpenCV 备用实现 |
| P2 | 动作模型接受非有限数值；训练接受零特征、样本数量不一致等数据 | 在模型加载及训练入口检查数据 |
| P2 | 离线视频脚本接受零步长，模型初始化失败后未释放视频资源 | 校验参数和写入器状态，使用统一退出清理 |
| P2 | 检测演示在导入时解析参数、下载模型，查看帮助也依赖联网 | 参数解析移入入口，默认使用本地模型 |

人体检测与姿态预处理的回归测试使用构造输入，可直接复现错误。
采样、线程、配置和发送返回码也有独立回归测试。
修复前的失败输出保存在 `regressions_before.log`、`lifecycle_before.log`
