# 现场测试记录

适用日期：2026-11-10。

现场测试记录用于真实摄像头、实际 RFID 和生产消息服务器验证。
它记录软件实际观察到的结果，不能代替人工确认身份是否正确。

## 使用方式

1. 在“现场测试”页启用“现场测试记录”。
2. 填写测试编号、记录人员、测试地点、测试场景和测试说明。
3. 启动联调，按场景执行测试。
4. 每次观察完成后填写预期结果、实际结果和结论。
5. 失败或待核对时，填写截图编号、视频时间点或 RFID 事件编号。
6. 停止联调后，保存本次会话目录。

## 自动记录

`field_test.json` 保存测试元数据和会话结果，主要字段包括：

- `test`：测试编号、人员、地点、场景和说明。
- `started_at`、`ended_at`、`duration_ms`：会话时间。
- `runtime`：是否为发布包、Python 版本和 Windows 环境。
- `configuration`：消息方式、视频地址摘要、启用区域、识别阈值、识别间隔和画面尺寸。
- `counts`：消息、旅客、绑定、未绑定、错误和未发送数量。
- `event_counts`：识别、绑定、人工核对、MQTT 状态和后台错误数量。

`field_test_events.jsonl` 每行是一条事件，事件类型包括：

- `session_started`、`session_stopped`
- `person_collected`
- `recognition`
- `binding_decision`
- `mqtt_state`
- `worker_error`
- `manual_observation`

识别事件保存采集时间、完成时间、区域、轨迹、候选身份、分数、状态、
位置框和性能指标。事件不保存视频帧和图片编码正文。

## 现场测试项目

| 项目 | 建议记录内容 |
| --- | --- |
| 闸机抓拍 | 应抓到人数、实际人数、漏抓、重复抓拍、图片清晰度、旅客编号 |
| 旅客入库 | 入库时间、图片来源、完整旅客编号、图片与现场人员是否对应 |
| 重识别 | 预测身份、实际身份、相似度、第二名分数、分数差、锁定状态 |
| 目标跟踪 | 遮挡返回、离开清除、队首切换、轨迹编号连续性 |
| 行李框绑定 | RFID、预期旅客、实际旅客、状态、依据、位置时差、停留时长 |
| 消息链路 | 主题、消息数、接收时间、重复事件、无效消息、重连、未发送 |
| 性能 | CPU/GPU、采集帧率、识别帧率、处理耗时、位置延迟、跳帧数 |
| 环境条件 | 摄像头位置、分辨率、光照、遮挡、人数、网络、截图和视频时间点 |

后续测试报告可以按“测试场景、输入条件、预期结果、实际结果、证据文件、
结论和问题”整理。`messages.jsonl` 用于消息时序，`field_test_events.jsonl`
用于识别和人工核对，`decisions.jsonl` 用于绑定依据，`performance.jsonl`
用于性能统计，`runtime.log` 用于错误和连接过程。
