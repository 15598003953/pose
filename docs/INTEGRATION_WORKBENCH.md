# 三部分联合调试工作台

日期：2026-11-03

## 启动

现有 Conda `mmpose` 环境已经补齐联合调试依赖。没有重建环境，也没有替换原项目入口。
`requirements-integration.txt` 记录额外依赖和参考版本，当前机器无需再次安装。
其他机器应先确认 PyTorch、CUDA 和 OpenCV 的兼容性；尚未验证从零重建整个环境。
Ultralytics 的依赖元数据使用 `opencv-python` 包名，本项目使用 `opencv-contrib-python`。
批量安装前应检查解析结果，避免同时安装两套提供 `cv2` 的包。

```powershell
conda run --no-capture-output -n mmpose python D:\code\mediapipe-master\pose\start_integration.py
```

其他入口：

```powershell
D:\code\mediapipe-master\pose\start_integration.cmd
conda run --no-capture-output -n mmpose python -m pose_project integrate
```

程序打开一个新设计的 PyQt5 窗口。它直接复用算法和后台任务，不打开、隐藏或嵌入原来的三个窗口。

## 界面安排

| 位置 | 内容 |
| --- | --- |
| 顶部 | 启动、停止、保存配置、环境检查，以及各模块状态 |
| 左侧“视频” | 两路各自选择本地视频或 RTSP、方向、模型和输出位置 |
| 左侧“区域” | 抓拍区、A/B 识别区、A/B 操作区，支持在预览上拖动框选 |
| 左侧“连接” | 本机直连或 MQTT、统一服务器、认证和消息主题 |
| 左侧“算法” | 重识别阈值、停留时间、位置有效期、采集条件 |
| 中间 | 闸机抓拍与供框台识别两路画面 |
| 下方标签页 | 绑定结果、消息正文、旅客库、运行日志 |
| 底部 | RFID 测试事件注入与手动上半身图导入 |

消息列表最多显示 500 条，运行日志最多显示 2000 行。完整日志保存在本次会话目录。
旅客图片消息的正文预览隐藏 base64 内容，只显示编码长度。
模型推理在后台线程运行，停止操作等待后台任务退出，不强行终止线程。

## 首次调试顺序

1. 为闸机选择“本地文件”或“RTSP / 网络流”，选择文件或填写地址。读取首帧，确认是否需要旋转 180°。
2. 为供框台选择文件或填写 RTSP 地址。读取首帧，确认画面方向和尺寸。
3. 在“区域”中框选闸机抓拍区。
4. 启用供框台 A 区或 B 区，框选识别区及其内部的操作区。
5. 确认采集条件、绑定参数，点击保存配置。
6. 点击“启动联调”。旅客图片自动进入重识别人物库。
7. 查看消息中的完整旅客编号和人员位置。
8. 在底部填写行李框 RFID，发送测试事件，检查结果及判定依据。
9. 停止后查看会话目录中的日志，再调整参数开始新会话。

更换画面尺寸时，程序按比例换算现有区域。更换摄像头或画面内容后，仍要重新标定。
工作台启动后锁定配置，修改配置前需要停止当前会话。

## RTSP 摄像头

两路可以同时使用 RTSP，也可以一路文件、一路 RTSP。
在“视频”页分别选择“RTSP / 网络流”，输入摄像头地址，然后点击右侧“读取首帧”图标。
例如：`rtsp://用户名:密码@192.168.1.10:554/stream`。
地址中的路径以摄像头配置为准，用户名或密码包含特殊字符时应先作 URL 编码。
粘贴完整地址后，界面自动选择网络流模式。

预览成功后标定区域，再启动联调。保存配置后，终端 `--headless` 也使用同一地址。
RTSP 优先使用 TCP，首次连接失败后尝试 UDP；断流时按原取流器的规则重连。
后台只保留最新一帧。闸机抓拍时间、供框台位置时间均来自收到画面的时刻。
这些时间不等于摄像头曝光时间。实时流忽略闸机原有的文件起始时间覆盖。
停止及关闭预览会请求退出取流，正在等待网络时需要等到底层读取超时。
连接和读取有超时限制，不使用无超时的备用打开方式。

RTSP 地址会随视频源保存在配置与会话快照中，地址内的摄像头账号密码也会一并保存。
MQTT 密码仍不保存。对外分享配置前，请移除摄像头账号密码。

## 两种连接方式

### 本机直连

默认模式，不连接 MQTT。三部分通过同一消息队列连接，消息字段仍采用既有协议。
RFID 测试事件进入同一接收流程。没有设备时，可以先检查编号、坐标和判定逻辑。

### MQTT 联调

三部分使用统一配置，所有内部人员图片、位置和 RFID 消息均通过指定服务器。
现有服务器必须提前启动。工作台不会启动或管理服务器。

| 用途 | 默认主题 |
| --- | --- |
| 旅客图片 | `check_gate/person/collected` |
| 人员位置 | `reidtest` |
| RFID 事件 | `pose/rfid` |
| 成功绑定输出 | `pose/bindings` |

四个主题必须互不相同。发布使用 QoS 1，不设置保留消息。
断开时保存有上限的待发送队列；重连后发送原消息，不修改位置时间。
停止时，日志会记录尚未发送或确认的消息数量。
“发送绑定结果”默认关闭，启用后只发送成功绑定的三个字段。
在 MQTT 模式下点击底部测试注入，会向所选服务器发送测试消息。

密码可在界面填写，或在终端设置 `MQTT_PASSWORD`。
密码不写入配置或会话快照。当前工作台不管理证书文件，仅支持系统信任链 TLS。

## 联调入口处理的接口问题

- 统一服务器与主题，保留原有独立程序的配置。
- 人物库始终使用上游完整 `passenger_id`。本地编号只用于界面显示。
- 同一旅客的新图片更新原条目。人物库最多保存 256 人。
- 人物库变化后，重建匹配数据并清除旧匹配历史。已加载的检测模型继续复用。
- 同一身份命中多个目标时，本帧不采用该身份，并记录原因，不随意选择一个目标。
- 文件回放使用当前会话时间与视频帧位置建立时间对应，落后时跳过旧帧。
- RTSP 时间记录取流端实际收到画面的时刻，不代表摄像机曝光时刻。
- 同一画面不会因为重复发送而得到新时间。没有新画面时，不发送假的新位置。
- 画面尺寸与区域不一致时，程序明确报告错误，不自动猜测坐标。
- 每次会话单独保存采集结果和编号映射，避免复用上一轮的本地编号记录。

以上调整仅适用于新联调入口。旧独立界面的身份选择、发布节奏等行为没有全面修改。
绑定核心算法仍使用原有规则，姿态动作分类不参与绑定。

## 终端检查

```powershell
conda run --no-capture-output -n mmpose python D:\code\mediapipe-master\pose\start_integration.py --check
conda run --no-capture-output -n mmpose python D:\code\mediapipe-master\pose\start_integration.py --self-test
conda run --no-capture-output -n mmpose python D:\code\mediapipe-master\pose\start_integration.py --headless --duration 60
```

`--check` 检查当前解释器、依赖和本地模型文件。
`--self-test` 使用模拟位置消息检查绑定，不运行模型或摄像头。
`--headless` 使用已保存的配置启动真实后台任务，只输出终端日志。
按 Ctrl+C 请求停止。`--duration` 设置自动停止时间，单位为秒。

可用 `--config <完整 JSON 路径>` 指定另一份配置。
图形界面的保存按钮只写入所选联调配置，旧配置文件不变。

## 输出与验证边界

每次运行创建新目录，其中包括：

```text
settings.json       本次配置，不含密码
runtime.log         各模块日志
messages.jsonl      接收消息，图片编码只记录长度
decisions.jsonl     绑定判定、候选旅客和停留依据
summary.json        停止后的统计
gate/               抓拍图片、人员汇总与编号映射
```

本地模型验证脚本：

```powershell
conda run --no-capture-output -n mmpose python D:\code\mediapipe-master\pose\scripts\verify_integration.py --output D:\code\mediapipe-master\pose\result\integration_verify_new
```

脚本从已有视频生成短片，运行实际采集、YOLO 和 FastReID，并检查界面与停止流程。
该检查中手动提供一张人物参考图；短片不代表闸机已经成功自动抓到对应旅客。
RFID 测试事件也不是真实硬件事件。位置过期或停留不足时，未绑定是预期保护行为。

真实摄像头、实际 RFID、现场服务器和识别正确率仍需联调。
本机同时运行多个模型时，应观察消息时间与推理耗时，不能用放宽位置有效期代替性能验证。
